# Neko Nap Webプロトタイプ設計書

ステータス: Implemented v0.7

最終更新日: 2026-08-13

議論元: [ChatGPT共有会話](https://chatgpt.com/share/6a7c2be3-0d04-83ee-b5ce-9c60941ea8ac)

## 1. 目的

短時間で遊べて、親しみやすく、kawaii要素を持つロジックパズルが、プレイヤーの継続プレイを促せるか検証するため、全20ステージのWebプロトタイプを制作する。

広告、収益化、ネイティブアプリ化、大量の問題生成に進む前に、このプロトタイプでゲームループそのものの面白さを検証する。

本書を実装仕様の正本とする。議論元に含まれる検討途中の案と本書が矛盾する場合は、本書を優先する。

## 2. プロダクトコンセプト

### 一言で表すと

> この子たちはちょっぴり神経質。ほかの猫と目が合うと眠れないみたい。みんなが安心できる寝床を見つけよう。

英語版コピー:

> These nervous kitties cannot sleep while another sleeping cat is watching. Find a safe bed for every cat.

### プレイヤーに与える体験

プレイヤーの役割は、抽象的な駒を配置することではなく、猫たちが安心して眠れる場所を見つけてあげることである。対立を避けるゲームではなく、猫を気遣うcozyな体験を目指す。

### 設計目標

- 長い説明を読まなくても、盤面とアニメーションから理解できる。
- 片手で遊べるタップ操作だけで完結する。
- 1ステージを数十秒から数分で遊べる。
- 「候補を消す → 場所が確定する → さらに候補が消える」という推理の報酬を頻繁に発生させる。
- 公開する全ステージに一意解がある。
- 将来、多数の問題を生成・検証しやすい単純なルールにする。

### プロトタイプで扱わないもの

- 広告、課金、アカウント、クラウドセーブ、ランキング、デイリーチャレンジ。
- Android/iOSのネイティブプロジェクト。
- ゲームエンジン、物理演算、3D表現、ドラッグ＆ドロップ操作。
- 実行時のプロシージャル問題生成。
- 一意解にするためだけに追加する数字や特殊ヒント。

## 3. 基本ルール

### 3.1 盤面要素

ゲーム上の意味を持つマスは、次の3種類だけとする。

| 要素 | 意味 | 猫を置けるか | 視線を遮るか |
|---|---|---:|---:|
| 床 | 部屋を構成する装飾・通路 | いいえ | いいえ |
| 寝床 | 猫を寝かせる候補位置 | はい | いいえ |
| 家具 | 壁、棚、観葉植物など | いいえ | はい |

家具の見た目には複数のバリエーションを用意できるが、MVPではすべて同じ視線遮断機能を持つ。

### 3.2 猫の配置とクリア条件

- 猫は寝床にだけ配置できる。
- 各ステージには、寝かせる猫の数 `K` が指定される。
- 猫がちょうど `K` 匹配置され、眠っているどの2匹の猫の間にも視線が通っていなければクリアとなる。
- 猫自身は視線を遮らない。
- 空の寝床とプレイヤーが付けた印は視線を遮らない。
- 猫を置いた順番や、最終的な `×` 印の状態は正解判定に含めない。

### 3.3 視線ルール

- 視線は上下左右にだけ伸びる。
- 斜め方向の視線は存在しない。
- 視線は盤面の端、または最初の家具に到達するまで続く。
- 2つの寝床が同じ行または列にあり、その間に家具がなければ、両方に猫を置いたとき競合する。

例:

```text
🐱  ·  🐱    不正解: 間を遮るものがなく、視線が通る

🐱  🌿  🐱   正解: 家具が視線を遮る

🐱
·             不正解: 縦方向にも視線が通る
🐱
```

### 3.4 間違えたときの扱い

- ライフ、時間ペナルティ、ゲームオーバーは設けない。
- 気軽に試行錯誤できるよう、競合する配置も一時的には許可する。
- 配置済みの猫と競合する寝床もタップでき、猫を配置できる。操作自体は無効化しない。
- 競合している猫と、その間の視線を即座に優しく強調表示する。
- ゲーム側がプレイヤーの `×` 印を自動で追加・削除しない。

## 4. プレイヤー操作

寝床をタップすると、次の順序で状態が切り替わる。

```text
空 → 猫 → × → 空
```

必須操作:

- 一手戻す
- リセット
- ヒント

詳細:

- 配置済みの猫と競合する寝床は薄く表示するが、タップ操作は許可し、自動で `×` は付けない。
- 競合する猫を配置した場合は、猫と視線を赤系の色で強調して理由を示す。
- `×` は正解データではなく、プレイヤー自身が管理するメモとする。
- 「一手戻す」は、印の変更を含む直前のプレイヤー操作を取り消す。
- リセットはステージ開始時の状態に戻す。十分な操作履歴がある場合のみ、確認を表示する。
- 各操作の直後にクリア条件を自動判定する。

## 5. 数理モデルと一意解

各寝床をグラフの頂点として扱う。2つの寝床に猫を置いたとき互いの視線が通る場合、その頂点間に無向辺を張る。正解は、頂点数がちょうど `K` の独立集合である。

ステージが一意解を持つ条件は次のとおり。

```text
競合グラフに、要素数Kの独立集合がちょうど1つだけ存在する
```

一意解かどうかは、猫が配置された寝床の集合だけで判定する。操作順、`×` 印、アニメーション状態、左右対称に見える装飾は無視する。

### ソルバーのインターフェース

```ts
export type CellKind = "floor" | "bed" | "furniture";

export interface Position {
  row: number;
  col: number;
}

export interface Level {
  id: string;
  width: number;
  height: number;
  catCount: number;
  cells: CellKind[];
  initialCats?: Position[];
  title?: string;
}

export interface SolveResult {
  solutionCount: number;
  firstSolution?: Position[];
}

export function solveLevel(level: Level, limit?: number): SolveResult;
export function conflicts(level: Level, a: Position, b: Position): boolean;
```

ステージ検証時は、解を2つ発見した時点で探索を終了してよい。解が2つ以上ある場合は、いずれも同じ不採用結果になるためである。

```text
countSolutions(level, limit = 2):
  すべての寝床から競合グラフを構築する
  各候補頂点について「選ぶ／選ばない」を再帰的に探索する
  次の場合は枝刈りする:
    選択済み頂点数 > K
    選択済み頂点数 + 残り候補数 < K
    次の候補が選択済み頂点と競合する
  解の数がlimitに達したら終了する
```

コミットする全ステージは、次の条件を満たさなければならない。

- マス数が `width × height` と一致する。
- `K > 0` であり、寝床が `K` 個以上存在する。
- 初期配置の猫がある場合、異なる寝床に置かれ、互いに競合していない。
- 解がちょうど1つ存在する。
- 開発用データに期待する正解を保存する場合、その内容がソルバーの解と一致する。

## 6. 難易度モデル

### 6.1 再定義の背景

初回プレイテストでは、旧ステージ15付近まで難易度が低く、家具を挟んだ配置を本格的に考える旧ステージ20で初めて面白さが明確になった。

主な原因は、`盤面の列数 = 猫数` に近い問題が多く、「各列に1匹ずつ置く」と早い段階で推測できたことにある。家具が少ない盤面では、本来の特徴である「家具によって同じ行・列が複数の視線区間に分割される」というルールも十分に使われていなかった。

以後は盤面サイズや猫数ではなく、**家具で分割された視線区間同士の依存関係**を難易度の中心にする。

### 6.2 難易度の指標

次の指標をステージごとに記録する。

- 寝床数と猫数。
- 家具数と、家具によって分割される有効な視線区間数。
- 正解内で、同じ行または列に家具を挟んで共存する猫の組数。
- 競合グラフの密度。
- 最初から確定できる配置数。
- 各行・各列へ1匹ずつ置くという単純な仮説だけで解けるか。
- 1つの視線区間を選んだときに影響する、別区間の数。
- 人間向け基準ソルバーが必要とする仮定数。
- 矛盾を発見するまでの最大深度。
- 推理が連鎖する長さ。
- 一見置けそうだが、最終的には不可能になる寝床の数。

### 6.3 推理レベル

人間の推理過程を基準に、難易度を次の7段階へ再定義する。

| 難易度 | 必要な推理 |
|---|---|
| N0 | 操作と基本ルールの実演。推理は不要 |
| N1 | 1つの視線、または1つの家具による直接的な候補除外 |
| N2 | 家具で分割された2つの視線区間を比較し、区間内の定員を考える |
| N3 | 1つの仮定から「残りの猫を置く場所が足りない」という矛盾を見つける |
| N4 | 2〜3区間にまたがる候補消去と確定の連鎖を追う |
| N5 | 複数の仮定を比較し、離れた区間への影響から一方を棄却する |
| N6 | 複数の家具区間が循環的に依存する。長い連鎖または2段階以上の仮定が必要 |

N2以降を本作固有の面白さが始まる水準とする。新ステージ10は旧ステージ20相当のN3とし、それ以降はN2未満の問題を原則として休憩ステージにだけ使用する。

### 6.4 盤面採用基準

一意解であるだけでは、面白い問題とは判定しない。ステージ6以降は次の条件を満たす。

- 原則として家具を2個以上配置する。
- 正解に、同じ行または列で家具を挟んで共存する猫を最低1組含める。
- `幅 = 猫数` または `高さ = 猫数` の場合でも、各列・各行に1匹ずつとは限らない正解にする。
- 行または列ごとの猫数だけを数える方法では一意に決まらない。
- 少なくとも1つは「現在置けるが、選ぶと後で猫数を満たせない」寝床を含める。
- ステージ10以降は、独立した家具区間を2つ以上の推理で結び付ける。

休憩ステージでは推理連鎖を短くしてよいが、家具区間を無視して解ける旧来型の盤面には戻さない。

### 6.5 人間向け難易度評価器

`src/game/difficulty.ts` の評価器は、一意解ソルバーの探索量とは別に、プレイヤーが盤面から読み取れる構造を測定する。

主要指標:

| 指標 | 意味 |
|---|---|
| `columnCapacities` | 各列を単独で見たとき、家具で分割された区間に置ける猫の最大数 |
| `columnCapacitySlack` | 全列の最大収容数合計から、実際の猫数を引いた余裕 |
| `columnAllocationCount` | 列の最大収容数だけから考えた、猫数配分ベクトルの候補数 |
| `rowCapacitySlack` | 全行の最大収容数合計から、実際の猫数を引いた余裕 |
| `rowAllocationCount` | 行の最大収容数だけから考えた、猫数配分ベクトルの候補数 |
| `columnProfileCount` | 完成1手前の合法な部分配置に現れる列配分の種類数 |
| `rowProfileCount` | 完成1手前の合法な部分配置に現れる行配分の種類数 |
| `maxPlacementsPerJointProfile` | 同じ行・列配分を持ちながら、寝床位置が異なる部分配置の最大数 |
| `lateContradictionRatio` | 誤った寝床を選んでも、完成1手前まで矛盾が表面化しない割合 |

特に重要なのは `columnAllocationCount` である。

```text
columnCapacitySlack = 0
columnAllocationCount = 1
```

の場合、すべての列を最大数まで埋めなければ指定猫数に到達しない。そのため、ゲーム開始時点で列ごとの猫数が一意に決まり、列単位の局所問題として簡単に解けてしまう。

改訂後のステージ10以降では、少なくとも次を必須とする。

```text
columnCapacitySlack >= 1
columnAllocationCount >= 2
```

ステージ21以降では行方向にも同じ条件を適用する。ステージ31以降では、さらに `maxPlacementsPerJointProfile >= 2` を必須とする。

評価レポートは次のコマンドで表示する。

```bash
npm run analyze-levels
```

現行盤面への初回適用では、ステージ10〜50のすべてで列配分が開始時点から一意であることを検出した。これはプレイテストの指摘と一致するため、評価器を使って盤面を再生成・差し替えする。

### 7.1 難易度カーブ

- ステージ10、20、25、30、35、40、45、50を明確な山場にする。
- ステージ11、16、21、26、31、36、41、46を休憩にする。
- 休憩では盤面を小さくするだけでなく、推理連鎖を短くする。
- 山場の直後は新ルールを追加せず、同じ考え方を短く復習させる。
- ステージ50まで新しい盤面要素は増やさず、家具区間の組み合わせだけで深さを作る。

### 7.2 制作時の検証

各盤面は次の順序で採用判定する。

1. ソルバーで一意解を確認する。
2. 単純な「各行・各列に1匹」戦略だけで解けないことを確認する。
3. 正解に家具を挟んで共存する猫が含まれることを確認する。
4. 人間向け推理ログを生成または記録し、想定したNレベルと比較する。
5. 実プレイ時間、ヒント使用、誤配置、離脱を計測する。
6. 前後のステージと比べて簡単すぎる、または急に難しすぎる場合は配置を修正する。

## 8. チュートリアルとヒント

### チュートリアル

- ステージ1では寝床を光らせる、またはポインターを表示し、短い指示文を1つだけ出す。
- ステージ2では、2匹の間を結ぶ視線を一度アニメーションで示す。
- ステージ3では、同じ視線が家具によって遮られる様子を示す。
- ステージ4では、本作の核である「残りの猫をすべて置けるか考える」ことを教える。
- ステージ4以降はモーダル形式の説明を避け、盤面構成と任意のヒントで学ばせる。

### ヒント

ヒントでは正解全体を表示せず、論理的に有用な次の一手を1つ説明する。

推奨する文面:

> この寝床を選ぶと、残り2匹を寝かせる場所が足りなくなります。

MVPでは現在の状態と一意解を比較してヒントを作ってもよいが、UI上では可能な限り理由を説明する。ステージごとのヒント使用回数を記録する。

## 12. テストと品質基準

必須の単体テスト:

- 横方向と縦方向の視線。
- 家具による遮断と境界条件。
- 斜めにある寝床同士は競合しない。
- 猫と空の寝床は視線を遮らない。
- タップによる状態循環、一手戻す、リセット。
- 競合しない猫がちょうど `K` 匹いる場合だけクリアになる。
- 解が0個、1個、複数個の場合にソルバーが正しい結果を返す。
- 全20ステージがそれぞれ一意解を持つ。

プロジェクト作成後に使用するコマンド:

```bash
npm ci
npm test
npm run build
npm run validate-levels
```

CIでは、依存関係のインストール、型チェック、単体テスト、一意解検証、本番ビルドを実行する。

## 13. プロトタイプでの計測

バックエンドがない段階でも、イベントをローカルに記録するか、プレイテスト結果としてエクスポートできるようにする。

### ローカル保存

- クリア済みステージ、現在の進行状況、ステージ別の計測値を `localStorage` に保存する。
- セーブデータには、将来の形式変更に備えてスキーマバージョンを含める。
- プレイテスト結果を個人情報を含まないJSONとしてエクスポートできるようにする。
- 保存データが破損している場合は、安全な初期値へ戻し、ゲームを継続できるようにする。

ステージごとの計測項目:

- 開始とクリア。
- クリア時間。
- 操作回数。
- `×` 印を付けた回数。
- 一手戻す、リセット、ヒントの使用回数。
- 不正な配置・競合が発生した回数。
- リスタートと途中離脱。

プロトタイプで確認すること:

- 初見プレイヤーがステージ3までに視線と家具を理解できるか。
- ステージ4で先読みの必要性に気付けるか。
- どのステージで自発的にプレイをやめるか。
- ステージ11の休憩が継続プレイを回復させるか。
- ヒントが推理方法を教えているか、単に問題を飛ばす手段になっていないか。
- クリア直後に迷わず「次のステージ」を選ぶか。

最初の外部プレイテストで基準値を得るまでは、継続率などに固定の目標値を設定しない。

## 15. 実装順序

1. TypeScript、React、Vite、Vitestのプロジェクトを作成し、Node.jsとnpmの入力条件を固定する。
2. ステージとゲーム状態の型を定義する。
3. 視線判定と競合グラフ構築を実装し、テストする。
4. 解の個数を数えるソルバーとステージ検証機能を実装し、テストする。
5. ステージ1〜4を作成して検証する。
6. CSSによる仮素材を使い、盤面UI、タップ状態の循環、競合表示、一手戻す、リセット、クリア処理を実装する。
7. チュートリアル演出とヒント機能を追加する。
8. `localStorage` による進行保存と、プレイテストデータのJSONエクスポートを実装する。
9. スマートフォン縦持ちを優先し、PCにも対応したレスポンシブ表示とアクセシビリティをテストする。
10. ステージ1〜4の操作感と理解度をプレイテストし、必要な仕様調整を行う。
11. 初回プレイテストの結果を基に難易度をN0〜N6へ再定義する。（完了）
12. 旧ステージ1〜19を新ステージ1〜9へ圧縮し、旧ステージ20相当を新ステージ10として盤面を作り直す。（完了）
13. 家具区間を中心としたステージ11〜50を段階的に作成・検証する。（完了）
14. 人間向け推理ログとプレイテスト結果を用いて、Nレベルと実際の難しさを補正する。

### 初期実装の完了条件

最初の実装対象はステージ1〜4までとする。次の条件を満たした時点で、後半ステージの制作へ進む。

- ステージ1〜4がすべて一意解を持つ。
- 初見プレイヤーがステージ3までに視線と家具のルールを理解できる。
- ステージ4で「現在置けるか」だけでなく「残りの猫をすべて置けるか」を考える体験が成立する。
- タップ、競合表示、一手戻す、リセット、ヒント、クリア処理がモバイルブラウザで問題なく動作する。
- 進行状況と計測値を保存し、JSONとしてエクスポートできる。
